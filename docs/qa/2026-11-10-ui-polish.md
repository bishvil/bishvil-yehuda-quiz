# UI fixes and usability verification — 2026-11-10

Follow-up to [the screenshot audit](2026-11-10-ui-audit.md). These changes cover
administrator/author, live host and player flows. All data and authentication
fixtures used here were local and synthetic; no production system was changed.

## Changes verified

- Closed mobile navigation is inert. Open navigation traps keyboard focus,
  closes with Escape/navigation and restores focus to its trigger.
- Editor answer fields and actions have individual accessible labels and larger
  touch targets. Advanced branding/scoring settings collapse. Selecting a station
  on mobile moves focus and scroll to its heading. Reordering has a direct
  touch/keyboard alternative to dragging. First-move and combined content/reorder
  saves persist after reload. New rows are appended at a free server ordinal
  before the desired order is saved; retries reuse their resolved server IDs.
- Local participant preview uses the real presentation components, supports all
  station types and simulated location, traps/restores focus, and makes no game,
  session or answer mutations. Unfinished GPS setup remains visibly unfinished.
- GPS authoring offers place search, map selection/dragging, a radius preview,
  device location and explicit coordinate entry. No default unlock point is
  silently saved. Pending setup blocks launch; a late device-location callback
  cannot overwrite newer question edits or a more recent location choice.
  GPS unlock radius is explicitly distinguished from map-answer tolerance.
- Brand names/logos replace raw identifiers. Search failures are distinguished
  from an empty result; provider requests have a timeout and fallback.
- Host question/roster areas scroll independently within the viewport. Search,
  waiting filters and textual answer statuses remain usable with 100 players.
  Primary controls stay visible on desktop and mobile. Information stations have
  appropriate opening/closing labels and no meaningless answer/time counters.
- Join fields follow quiz configuration while retaining the existing required
  Google identity and phone policy. Information text uses readable body type.
  Untimed questions say so; revealed open answers show an accepted answer.
- GPS player view preserves quiz/station context, explains distance/accuracy,
  offers navigation, device-specific permission recovery and administrator help.
- Personal results offer an answer review. The server checks participant/session
  ownership and completion, selects only the current participant's answers, and
  excludes unopened/unrevealed scored questions. An early results request
  redirects back to play; an early review API request returns HTTP 409.
- Administrator reports distinguish information-only, unanswered and genuine
  zero accuracy. Statuses/CSV are in Hebrew. Mobile summaries are compact; open
  answers and location overrides have pending/error feedback and duplicate-click
  protection. A failed refresh preserves the existing report.

## Evidence and checks

Chromium at 1366×900 and 390×844; inspected screenshots, accessibility snapshots,
keyboard navigation, viewport/scroll measurements, real local API/database calls
and deterministic response fixtures for error states. No horizontal page overflow
was found in the verified screens. The 100-player host screen stays within a
900px desktop or 844px mobile viewport, with the roster scrolling internally.
Preview interactions produced zero game/session/answer API mutations.

Current-run artifacts are outside the source repository:
`/workspace/artifacts/quiz-ui-polish-2026-11-10/report.html`.
The report embeds the inspected screenshots. Authentication storage states are
excluded and removed after verification.

Automated final counts and build results are recorded in the final validation
section below. Five critical Playwright scenarios cover author/create/launch,
host transitions, content→untimed open→GPS→results, editor persistence, and map
label/style switching. Added unit/API cases cover accessibility, preview isolation,
draft-location races, result semantics, review ownership and answer secrecy.

## Remaining release checks

This is an expert/browser review, not user research or a full accessibility
certification. Physical Android/iPhone GPS, Safari, screen-reader use, live Google
OAuth and live map settlement/RTL coverage still require release-device checks.
The map renderer/labels and radius overlay were exercised with a deterministic
style because outbound tile/RTL provider access is blocked in this environment;
the neutral map background in the screenshots is a test fixture.

The question-capability migrations and deployment order remain as documented in
[capability release verification](2026-11-10-question-capabilities.md). Production
migrations/deployment have not run; the task environment has no connected
Supabase/Vercel deployment credentials. The follow-up also adds
`20261110090300_atomic_question_reorder.sql`, to apply after those three migrations;
it makes bulk reorder a service-only database transaction with rollback and
complete-set validation.
